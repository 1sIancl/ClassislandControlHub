# 班级看板 功能规格（Class Board Spec）

> 版本：对应 `?v=173`
> 范围：班级大屏看板（`#/classboard`）、外观配置、天气展示。
> 本文档所有行为描述均以**当前实现**为准；标 ✅ 的条目已有自动化断言，标 ⬜ 的尚无。

---

## 1. 目标用户与使用场景

| 角色 | 场景 | 关键诉求 | 现状 |
|---|---|---|---|
| **学生**（被动观看者） | 课间抬头看教室大屏 | 现在几点、这节什么课、还剩多久 | 主用户，**无任何可点击入口** |
| **班主任 / 任课老师** | 课前确认下一节、临时发布通知 | 改公告、调字号让最后一排看清 | 通过管理台改数据；外观在本机调 |
| **信息管理员** | 开学装机、换教室 | 一次部署多间教室、排障 | 通过 URL 指定档案 ID 分发 |
| **值班/巡查** | 路过确认屏幕正常工作 | 一眼看出是否"卡住了" | 时钟走秒即为活性信号 |

**明确不服务的角色**：家长、外部访客。看板不含任何学生个人信息（成绩、考勤、姓名），只有课程与公告。

**典型使用路径**

```
装机：管理员把浏览器指向 #/classboard/{档案ID} → 全屏（F11）→ 投到教室大屏
日常：自动走秒 + 每 60 秒刷新，无人干预
变更：老师在管理台改公告/课表 → 看板 60 秒内自动更新，无需操作
调外观：老师点右下齿轮 → 选主题/字号 → 立刻生效并记住
```

## 2. 核心功能点

### F1 大时钟与日期 【必须】

| 项 | 内容 |
|---|---|
| 输入 | 浏览器本地时间 |
| 处理 | 每 1000ms 更新时钟文本；**只改两个 DOM 节点的 textContent**，不重建页面 |
| 输出 | `HH:mm:ss`（补零）+ `YYYY 年 M 月 D 日` + 星期 |
| 依赖 | 无 |
| 备注 | 走秒本身是"活着"的信号：秒不动 = 页面卡死，巡查一眼可判 |

### F2 当前课程定位 【必须】

| 项 | 内容 |
|---|---|
| 输入 | 档案内容（`classPlans`、`timeLayouts`、`subjects`）+ 当前时间 |
| 处理 | ① 按 `new Date().getDay()` 找当天课表（`daysOfWeek` 包含今天且 `isEnabled !== false`，否则退回任意含今天的）；② 取该课表 `timeLayoutId` 对应时间表里的 `kind === 'class'` 条目；③ 按 `startTime/endTime` 转分钟数与当前时刻比较 |
| 输出 | 三态：`in-class`（进行中）/ `before`（未开始）/ `after`（已结束）+ 当前或下一节的科目名、教师、起止时间、剩余分钟 |
| 依赖 | F4（无课表时的降级） |

**判定规则（必须精确，否则会误报"上课中"）**

```
现在 ∈ [start, end)          → 进行中
现在 < 最近一个尚未开始的 start → 未开始
其余                          → 已结束
```

### F3 今日课表列表 【必须】

| 项 | 内容 |
|---|---|
| 输入 | 同 F2 |
| 处理 | 全部上课条目按时间排序渲染；进行中的行高亮，已过的行透明度 0.38 |
| 输出 | 行：`节次 | 科目 | 起–止`；无科目时显示 `—` |
| 依赖 | F2 |
| 备注 | 列表高度自适应，条目多时**不滚动**（由行高压缩承担，见 NFR-1） |

### F4 无课时降级：预告下一个上学日 【必须】

| 项 | 内容 |
|---|---|
| 输入 | 同 F2 |
| 处理 | 当天无课时，从今天起最多往后找 7 天，取第一个有课的日子 |
| 输出 | 标题「{周X}的课表」+ 该日完整列表 + 副标题「今天没课 · 下次是{周X}」 |
| 依赖 | 无 |
| 为什么必须 | 周末看板空着等于这块屏周末废了；学生周末也会看到它 |

### F5 公告展示 【重要】

| 项 | 内容 |
|---|---|
| 输入 | `profile.content.settings.announcement`（纯文本/Markdown 原文） |
| 处理 | 右栏卡片原样显示，保留换行（`white-space: pre-wrap`） |
| 输出 | 公告卡片；内容为空则不渲染该卡片（**不留空框**） |
| 依赖 | 档案接口 |

### F6 顶部滚动条 【重要】

| 项 | 内容 |
|---|---|
| 输入 | 同 F5 |
| 处理 | 文本长度 **≥ 16 字符**才滚动；CSS 动画横向跑马灯，首尾各复制一份内容实现无缝；遵守 `prefers-reduced-motion`（该偏好下静止显示） |
| 输出 | 顶部红色条幅；不满足条件则不渲染 |
| 依赖 | F5 |
| 为什么不复用公告卡片 | 卡片适合停下来读；滚动条适合"必须被看见"。**角落里的通知等于没发** |

### F7 天气展示 【重要】

| 项 | 内容 |
|---|---|
| 输入 | `GET /admin/weather` 返回的 `available / temperature / temperatureText / summary / source` |
| 处理 | 前端**只读不解释**：温度取 `temperature`+`temperatureText`，描述直接用服务端拼好的 `summary` |
| 输出 | 温度大字 + 摘要 + 数据来源 |
| 依赖 | 天气功能已启用且有数据 |
| 备注 | 天气代码→中文的映射在服务端只有一份，前端再猜一遍会长出第二套说法（同一个 4° 两处显示不同） |

### F8 外观配置 【重要】

| 项 | 内容 |
|---|---|
| 输入 | 右下角齿轮 → 面板操作 |
| 处理 | 读写 `localStorage['islandhub.classboard.style']`，改完立即重画（不刷新） |
| 输出 | 主题（深/浅）、主色（4 色）、时钟大小（大 1.0 / 中 0.74 / 小 0.56）、天气/公告/滚动条开关 |
| 依赖 | 无（纯前端） |
| 配置不落库的理由 | 这是"这台机器那块屏"的偏好；放进档案会让"改个配色"变成一次全校下发 |

### F9 自动刷新 【必须】

| 项 | 内容 |
|---|---|
| 输入 | 定时器 |
| 处理 | 每 60000ms 重新拉档案与天气并重画；失败**保持上一屏** |
| 输出 | 无可见提示（大屏上跳错误框比数据旧一分钟更难看） |
| 依赖 | 无 |

### F10 页面退出 【可选】

右下角 12px、透明度 22% 的「退出看板」链接，回配置档案列表。老师偶尔需要，学生不会注意。

## 3. 依赖关系与优先级

```
F1 时钟 ─────────────── 独立
F5 公告 ──┐
          ├─→ F6 滚动条（依赖公告文本）
F2 定位 ──┴─→ F3 列表 ──→ F4 无课时降级
                    │
F7 天气 ────────────┤ 独立
F8 外观配置 ────────┤ 独立（只影响渲染表现）
F9 自动刷新 ────────┘ 依赖 F2/F5/F7 的数据源
```

| 优先级 | 功能 | 判定依据 |
|---|---|---|
| **必须** | F1、F2、F3、F4、F9 | 缺任一项，看板不成立（没有时钟就只是张课表） |
| **重要** | F5、F6、F7、F8 | 直接影响可用性；缺失时降级可接受 |
| **可选** | F10 | 没有也不影响日常使用 |

**强依赖提示**：F2/F3/F4 全部依赖「档案内容里有 `timeLayouts`」这一前提。时间表升为全局实体后，服务端读取档案时会做投影（`TimeLayoutLibrary.ProjectAsync`），看板拿到的是**库里的最新内容**，而非档案里的旧快照——这是"改了时间表，看板跟着变"的前提，不可绕过。

## 4. 边界条件与异常处理

| # | 情况 | 预期行为 | 状态 |
|---|---|---|---|
| B1 | 没有配档案 | 显示「还没有配置档案」提示，不白屏 | ✅ |
| B2 | URL 未带档案 ID | 用默认档案；没有默认则用第一个 | ✅ |
| B3 | 档案存在但无课表 | F4 降级到"下一个有课的日子"；一周都无课则显示「今天没有课」 | ✅ |
| B4 | 课表引用的时间表在库里不存在 | 服务端用档案自带快照兜底；仍无则跳过该表 | ✅ 后端 |
| B5 | 时间点 `startTime` 缺失或非法 | 该条目视为无效，不计入列表（当前实现：分钟数解析失败则跳过比较） | ⬜ 需补测 |
| B6 | 跨零点时间点（如 23:50–00:20） | 当前按当天分钟数比较，会判成负时长 → **已知限制**，需明确不支持或按 +24h 处理 | ⬜ 待定 |
| B7 | 公告为空字符串 / 全空白 | 不渲染卡片，也不渲染滚动条 | ✅ |
| B8 | 公告 < 16 字符 | 不渲染滚动条（短文本滚动比静止更难看） | ✅ |
| B9 | 公告超长（> 2000 字） | 卡片区域内容过多 → 需限高+内部省略（**当前未处理**） | ⬜ 待补 |
| B10 | 无天气数据 / 天气未启用 | 不渲染天气卡片，其余正常 | ✅ |
| B11 | 天气接口超时 | 服务端 15 秒超时并清空 `summary`；前端视为无数据 | ✅ |
| B12 | 天气字段为 `null` | 温度显示 `0°C` 是**错的**，应显示 `--` | ⬜ 待修 |
| B13 | 档案接口 500 / 网络断开 | 首次加载显示错误块；运行中静默保持上一屏 | ✅ |
| B14 | localStorage 被禁用 / 内容损坏 | 退回默认外观，看板照常打开 | ✅ |
| B15 | localStorage 里存了非法值（`theme: "浅色"`） | 需白名单校验后才应用，否则样式全部失效 | ⬜ 待补（本轮踩过） |
| B16 | 浏览器处于 `prefers-reduced-motion` | 滚动条静止显示 | ✅ |
| B17 | 页面切走 / 标签页关闭 | `container.isConnected === false` 时清掉两个定时器，避免泄漏 | ✅ |
| B18 | 系统时间被改 | 时钟与课表定位同步变化（都以本机时间为准），不接受服务端授时 | 说明 |

## 5. 非功能性要求

### NFR-1 性能

| 指标 | 要求 | 现状 |
|---|---|---|
| 首屏可读 | ≤ 3 秒（内网） | 约 1.5–2.5 秒（两次接口串行） |
| 走秒开销 | 每秒 ≤ 2 次 DOM 写入，**不得重建节点** | ✅ 只写 2 个 textContent |
| 常驻内存 | 24 小时运行不得持续增长（定时器必须可清） | ✅ `stopTimers()` |
| 网络 | 空闲时每分钟 2 个请求（档案 + 天气） | ✅ |
| 无滚动条 | 课表条目多时压缩行高而非滚动 | ✅ 10 节课 1366×768 一屏 |

### NFR-2 安全

- 看板页**只读**：无任何写操作入口，学生无法改数据。
- 权限：路由要求 `profiles.read`；未登录跳登录页。
- 公告内容是**纯文本渲染**，不得 `innerHTML` 注入（防 XSS）。
- 不显示任何学生个人身份信息。

### NFR-3 兼容性

| 项 | 要求 |
|---|---|
| 分辨率 | 1280×720、1366×768、1440×900、1920×1080 均完整显示 |
| 浏览器 | Edge / Chrome 最近两个大版本（教室机通常是旧版 Edge，需实测） |
| 字体 | 时钟用等宽字体 + `tabular-nums`，避免走秒时数字抖动 |
| 缩放 | 125% / 150% 系统缩放下列表不裁切 |

### NFR-4 可维护性

- 文案全部走 i18n 键，禁止硬编码中文（键覆盖检查已纳入门禁）。
- 单文件单一职责：`classBoard.js` 只负责渲染，数据获取集中在 `loadBoard()`。

## 6. 验收标准

每条都可被自动化断言（括号内为判定方式）。

### 必须（Must）

| # | 验收标准 | 验证方式 |
|---|---|---|
| AC-1 | 打开 `#/classboard` 后 3 秒内出现大时钟，且格式为 `HH:mm:ss` | 断言 `.classboard-clock` 文本匹配 `/^\d{2}:\d{2}:\d{2}$/` |
| AC-2 | 时钟每秒钟变化 | 间隔 1.2 秒读两次，值不同 |
| AC-3 | 时钟区域内不存在可点击的写操作按钮 | 断言 `.classboard` 内 `button` 数 = 1（仅齿轮）+ 1 个退出链接 |
| AC-4 | 有课时列表渲染出**全部**上课条目 | 断言 `.classboard-row` 数量 == 时间表内 `kind==='class'` 条目数 |
| AC-5 | 进行中的一节有 `.active` 类，且只有一节 | 断言 `.classboard-row.active` 数 ∈ {0,1} |
| AC-6 | 当天无课时显示下一个上学日的课表 | 构造只有周一有课的档案，在周日打开，断言出现「周一的课表」且行数 > 0 |
| AC-7 | 60 秒后自动刷新，且不黑屏 | 修改公告 → 等待 ≤ 65 秒 → 断言公告文本已更新 |
| AC-8 | 页面切走后不再有定时器在跑 | 切路由后等待 2 秒，断言无 `pageerror`、且时钟节点已卸载 |
| AC-9 | 1280×720 到 1920×1080 均无纵向/横向滚动条 | 断言 `scrollHeight - clientHeight <= 2` 且 `scrollWidth - clientWidth <= 2` |

### 重要（Should）

| # | 验收标准 | 验证方式 |
|---|---|---|
| AC-10 | 公告为空时不渲染卡片也不渲染滚动条 | 断言 `.classboard-card` 中无「公告」标题且 `.classboard-marquee` 不存在 |
| AC-11 | 公告 ≥16 字符时出现滚动条，且文本完整 | 断言 `.classboard-marquee-inner` 文本包含公告全文 |
| AC-12 | 滚动条不遮挡顶部日期 | 断言 `.classboard-top` 的 `top` ≥ 滚动条高度 |
| AC-13 | 齿轮可打开配置面板，含 4 组配置 | 断言面板内 `.classboard-config-chip` ≥ 8 且 `.classboard-config-dot` == 4 |
| AC-14 | 切换主题立即生效且可读 | 点「浅色」→ 断言 class 含 `theme-light`，且 `.classboard-row` 计算色亮度 < 阈值（非浅色文字） |
| AC-15 | 切换时钟大小改变字号 | 记录字号 → 点「小」→ 断言字号比例 ≈ 0.56 |
| AC-16 | 关闭「天气」后天气卡片消失 | 点开面板关天气 → 断言无 `.classboard-weather-temp` |
| AC-17 | 配置刷新后仍然保留 | 写入后 `location.reload()` → 断言 class 仍为所选主题 |
| AC-18 | 天气字段缺失时不显示 `0°C` | 构造 `temperature: null` → 断言显示 `--` |
| AC-19 | 天气接口失败时其余模块正常 | 拦截 `/admin/weather` 返回 500 → 断言时钟与课表仍渲染 |

### 可选（Could）

| # | 验收标准 |
|---|---|
| AC-20 | 退出链接可回到配置档案列表 |
| AC-21 | `prefers-reduced-motion` 下滚动条静止（无 animation） |
| AC-22 | 公告超长时卡片内省略而非撑破布局 |

## 7. 当前已知缺口（未达标的验收项）

| 对应 | 缺口 | 影响 |
|---|---|---|
| AC-18 / B12 | 天气温度 `null` 时显示 `0°C` | 数据异常时给出**错的气温**，比不显示更糟 |
| AC-16 相关 / B15 | 配置值无白名单校验 | 存了非法值会让样式全部失效（本轮已踩） |
| B9 / AC-22 | 超长公告未限高 | 卡片会撑破右栏 |
| B6 | 跨零点时间点未处理 | 夜班/寄宿学校会算错 |
| — | **天气预警未接入** | Open-Meteo 不提供预警数据；参考站点显示预警是另接了国内源（NMC / 和风 / 彩云）。当前由公告承载警示信息，**不做假数据占位** |

> 这 5 条按顺序修，前 3 条是小改动且直接影响"异常情况下是否正确呈现"，建议优先。
