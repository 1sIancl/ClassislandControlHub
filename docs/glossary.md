# 术语表（界面文案的统一叫法）

这份表解决一个很具体的问题：**同一个东西在不同页面被叫成好几个名字**，用户以为是不同的功能，
新人读代码也拼不出全貌。下面「统一叫法」用于界面文案与新增文档；「代码里的对应物」是实际实现，
**不要为了统一叫法去改代码/接口/动作码**（那会破坏兼容性，收益也远小于风险）。

## 一、核心概念

| 统一叫法 | 不要叫 | 代码里的对应物 |
|---|---|---|
| **配置档案** | 配置、方案、模板、profile | `profiles` 表 / `ProfileRow` / `#/profiles` |
| **课表** | 课程表、排课 | `ClassPlan` / 档案内容里的课表部分 |
| **时间表** | 作息表、时间安排 | `TimeLayout` |
| **科目** | 学科、课程 | `Subject` |
| **教室** | 班级、终端（指一台设备时用「教室」） | `devices` 表 / `DeviceRow`（界面里显示为「教室 · xxx」） |
| **楼栋 / 楼层** | 楼、建筑 / 层 | `groups` 表（`kind='building'` 的是楼栋，`parent_id` 指向楼栋的是楼层） |
| **分组** | 分类、标签 | `groups` 表；**标签是另一个概念**（横切维度，见下） |
| **集控服务器** | A 端、服务端、管理端 | `ControlHub.Server`；界面上称「服务器信息」 |
| **教室端** | B 端、客户端、插件、接收端 | `ControlHub.Plugin`（跑在教室电脑的 ClassIsland 里） |
| **桌面外壳** | 桌面端、客户端程序 | `ControlHub.Desktop`（Windows 托盘程序，用于本地启停服务器） |

## 二、容易混的几组

| 概念 | 区别 |
|---|---|
| **分组 vs 标签** | 分组是**物理层级**（一栋楼一层楼，一台设备只属于一个）；标签是**横切维度**（一台设备可以有多个标签，如「高考考场」「待维修」）。两者正交，不互相替代。 |
| **在线 vs 同步** | 「在线」= 最近有心跳（由 `OnlineTimeoutSeconds` 判定）；「同步」= 已应用到最新配置版本号。一台设备可以在线但待同步。 |
| **指令 vs 通知** | 「指令」是要设备**执行**动作（重启/关机/截图等）；「通知」是让屏幕**显示**内容。指令有执行结果（成功/失败），通知只关心有没有展示。 |
| **档案 vs 版本** | 一台设备绑一份档案；档案每次编辑产生一个新版本号。设备上报的是「我应用到了哪一版」。 |

## 三、状态用词（设备）

界面上一律用这几个词，与 `views/devices.js` 的 `STATE_LABEL` 保持一致：

| 用词 | 含义 |
|---|---|
| **在线** | 有心跳，且已应用最新配置 |
| **待同步** | 在线但还没应用最新配置 |
| **同步中** | 正在拉取配置 |
| **异常** | 设备自报出错（`state === 'error'`），需看日志 |
| **离线** | 超时未收到心跳 |
| **已停用** | 被管理员撤销（`revoked`），不再接受指令 |

## 四、动作码（审计日志）

审计日志里的动作码（如 `profile.duplicate`）**属于对外契约，不改名**。
界面上通过 `core/audit-actions.js` 映射成中文显示，例如：

| 动作码 | 界面显示 |
|---|---|
| `profile.duplicate` | 复制配置档案 |
| `device.command` | 下发指令 |
| `admin.login` | 登录管理端 |

新增动作时，**在 `audit-actions.js` 里补一条映射**即可；忘了补也不会坏（认不出的动作码直接显示原文）。

## 五、怎么写新文案

1. **标题说结果，正文说下一步**：`已下发` 不如 `已下发（45 台成功，3 台离线排队）`。
2. **不要用「操作」「处理」这类空词**：写清是什么操作。
3. **失败提示必须带「怎么办」**：见 `core/error-hints.js`，每个错误码都有对应建议。
4. **能用数字就别用形容词**：「设备较多」不如「45 台」。

> 注：本表是**文案规范**，不是重构计划。历史遗留的不同叫法在改动相邻代码时顺手统一即可，
> 不做「全局搜索替换」——那会误伤动作码、接口字段与注释里的专有名词。
