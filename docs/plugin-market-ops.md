# 插件市场运营手册（#104）

> 对象：负责「我们学校该装哪些插件」「我们自己的插件要不要上架」的人。
> 这份文档只写**流程与判断**；界面上能点的东西在「插件管理」页，字段细节见 [`plugin-protocol.md`](plugin-protocol.md)。

---

## 一、上架自检（先跑它，再谈提交）

「插件管理」每行有 **运营** 按钮，点开后「上架自检」会把审核清单里**能自动判断**的项跑一遍：

| 检查项 | 不通过通常意味着 |
|---|---|
| 插件 ID | 清单里没有 `id`，官方索引无法给它建条目 |
| 名称 / 版本号 / API 版本 | `manifest.yml` 缺字段；API 版本要与编译所用 PluginSdk 对齐 |
| 作者 / 简介 | 用户在列表里看到的全部信息就是这两项，空着等于没介绍 |
| 图标 / 自述文件 | 列表里会显示成默认图标；详情页没有说明 |
| 仓库地址 | 用户看不到源码与 issue 入口，出问题没人能反馈 |
| 安装包已缓存 | 教室端装不了（A 端还没有这个 `.cipx`） |

**自动判断不了的三件事**，只能人来把关：

1. **文案**：一句话说清"它解决什么问题"。不要写「XXX 增强插件」这种等于没说的。
2. **截图**：至少一张教室大屏上的实际效果（不是管理界面截图）。
3. **兼容性实测**：在**本机最低版本**的教室端上装一次、跑一次。

## 二、提交流程

```
① 本地跑一次上架自检（全绿）
② 打标签发版（流水线产出 .cipx）
③ 确认 Release 里有 .cipx，且 manifest 的 version 与标签一致
④ 提交到 ClassIsland 官方插件索引（见下）
⑤ 回来在本页「同步索引」，确认能搜到自己
⑥ 缓存安装包，然后在一台教室机上装一次做终验
```

- **官方索引**：ClassIsland 的插件市场由官方索引驱动（本仓 A 端只是代理缓存）。
  提交方式与字段要求以官方仓库说明为准；本仓的 `manifest.yml` 已包含
  `icon` / `readme` / `repoOwner` / `repoName` / `assetsRoot` / `artifactName` / `tagPattern` / `supportedOSPlatforms`。
- **发版即收录**：改版本号 → 打 `1.x.y.0` 标签 → 流水线产出 `.cipx` → 市场按版本号提示更新。
- **图标与自述文件**：A 端会按需代理下载并缓存（首次约 2 秒，之后 0.02 秒），
  所以**不要让它们依赖会失效的图床**——这也是本仓的一条既有教训（外链失效后界面会静默退回文字）。

## 三、运营标记（推荐 / 已弃用）

界面上的「运营」按钮可以给任意插件打标记，存在**独立表**里（不随市场索引同步被冲掉）：

| 标记 | 用在哪 | 备注里写什么 |
|---|---|---|
| **推荐** | 本校建议装的（例如班牌必装的那几个） | 谁批准的、实测可用的宿主版本 |
| **已弃用** | 与当前宿主不兼容、或已被更好的替代 | 为什么不推荐、替代品是哪个 |
| 普通（并清空备注） | 撤销标记 | — |

> 标记会自动记录**上一次人工验证时间**。三个月没人动过的"推荐"，值得重新验一遍。

## 四、维护节奏（建议）

| 频率 | 做什么 |
|---|---|
| 每次宿主大版本升级后 | 把「推荐」列表里的插件各装一次；不兼容的改标「已弃用」 |
| 每月 | 看一眼「可升级 N 台」的聚合，挑使用面最广的先升；同步一次市场索引 |
| 每学期 | 复盘一次「推荐」清单：还在用的留、没人用的撤；顺手清理 A 端缓存里的旧版本包 |

**升级顺序**：先在 1~2 间教室试（选「安装到教室」时只勾这两台）→ 看指令历史里的结果 →
再推到整栋楼。教室端装包失败会在指令状态里带错误码，见 [`command-codes.md`](command-codes.md)（若有）。

## 五、推广与案例征集

不做"广而告之"那种推广，只做三件对用户真有用的事：

1. **在本校群里发一条"这周装了什么、解决什么问题"**（一句话 + 一张大屏截图）。
2. **收集使用场景**：哪个班用它做了什么调整（换课 / 考试 / 停电应急）。
   攒够 3 个场景，就能写成一篇《我们学校怎么用 IslandHub》。
3. **给作者反馈**：装完第一周内，把遇到的问题（带日志与指令错误码）提到插件仓库的 issue。
   这一步对生态的贡献比"点个 star"大得多。

**案例征集模板**（直接复制改）：

```
场景：<一句话，例如"期中考试换场次">
原来怎么做：<手工改 12 个班的课表，约 40 分钟>
现在怎么做：<快捷换课 + 调休，约 3 分钟>
用到的功能：<快捷换课 / 调休 / 定时提醒>
坑：<例如"跨夜静默时段要避开考试开始时间">
```

## 六、常见问题

**Q：同步索引后我的运营标记还在吗？**
在。标记存在独立的 `plugin_ops` 表里，市场索引是整表替换的另一张表。

**Q：教室端装不上，先看哪里？**
「插件管理 → 下发记录」里的逐台结果；再看那台设备的 ClassIsland 版本是否满足插件要求的「要求 API」。

**Q：能不能只让部分教室看到某个插件？**
不能——市场是全校一份。要控制"哪些教室跑什么"，用「配置下发」的档案控制，而不是市场。
