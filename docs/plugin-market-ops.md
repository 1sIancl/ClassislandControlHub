# 插件市场运营

「插件管理」页每行有「运营」按钮：标推荐 / 弃用、写上架自检。

## 上架自检

自动检查 10 项：插件 ID、名称、版本、API 版本、作者、简介、图标、自述文件、仓库地址、安装包是否已缓存。
缺哪项会标红，补齐再提交。

自动判断不了、需要人工把关的三件事：

1. **文案**：一句话说清它解决什么问题。
2. **截图**：至少一张教室大屏上的实际效果。
3. **实测**：在本校**最低版本**的教室端上装一次、跑一次。

## 提交流程

1. 本地跑一次上架自检，全绿。
2. 打标签发版，流水线产出 `.cipx`。
3. 确认 Release 里有 `.cipx`，且 `manifest.yml` 的 version 与标签一致。
4. 提交到 ClassIsland 官方插件索引。
5. 回来「同步索引」，确认能搜到自己；缓存安装包后在一台教室机上终验。

## 运营标记

| 标记 | 用在哪 | 备注写什么 |
|---|---|---|
| 推荐 | 本校建议装的 | 谁批准、实测可用的宿主版本 |
| 已弃用 | 与宿主不兼容或已有替代 | 为什么不推荐、替代品是哪个 |
| 普通（清空备注） | 撤销标记 | — |

标记存在独立表里，不随市场索引同步被冲掉；每次保存会记「上次人工验证时间」。

## 维护节奏

- **宿主大版本升级后**：把「推荐」列表各装一次，不兼容的改「已弃用」。
- **每月**：看「可升级 N 台」，挑使用面最广的先升；同步一次市场索引。
- **每学期**：复盘推荐清单，撤掉没人用的；清理 A 端缓存里的旧版本包。

升级顺序：先 1~2 间教室试 → 看指令历史的结果 → 再推整栋。装包失败会在指令状态里带错误码。

## 常见问题

**同步索引后标记还在吗？** 在。标记在 `plugin_ops` 表，与市场索引是两张表。

**教室端装不上先看哪？** 「下发记录」里的逐台结果；再看那台设备的 ClassIsland 版本是否满足插件的「要求 API」。

**能只让部分教室看到某插件吗？** 不能，市场是全校一份。要控制「哪些教室跑什么」用配置档案，不用市场。
