# ADR-0004：远程截图走应用渲染管线，不用系统级抓屏

- 状态：已接受
- 日期：2026-10-02
- 相关：[USAGE「远程诊断」](../../USAGE.md)、[docs/troubleshooting.md](../troubleshooting.md)

## 背景

需要「远程看一眼教室端现在是什么样」。可选做法有两类：

1. **系统级抓屏**（`BitBlt` / `CopyFromScreen`）：抓整个桌面，能拿到其它窗口；
2. **应用渲染管线**（Avalonia `RenderTargetBitmap.Render`）：抓 ClassIsland 主界面本身。

值得注意的证据：ClassIsland 宿主自带的 `WindowCaptureHelper`（原本用于壁纸取色）**整个文件被 `#if false` 停用了**
——这是「系统级抓屏在硬件加速窗口上不可靠」的一手经验。

## 决策

**抓 ClassIsland 主界面的渲染画面**，而不是整个桌面。

## 理由

- **教室端通常全屏运行 ClassIsland**，它的界面就是学生看到的内容——排查「大屏显示不对」时，
  要的正是这个画面，而不是桌面（桌面上还有别的窗口、可能含无关信息）。
- **避免全黑图**：对使用硬件加速渲染的窗口做系统级 GDI 抓屏，很容易拿到全黑或残缺的图像，
  这类「看起来成功了但内容没用」的结果比明确失败更浪费时间。
- **隐私更收敛**：只取本应用界面，天然减少了抓取到教师私人窗口的风险（这也是教室端能放心给出开关的前提）。
- **不引入额外依赖**：渲染管线是应用自带的，无需 P/Invoke 与位图句柄操作，跨平台行为也更一致。

## 代价与限制（都已写进排查指南）

- 抓不到系统桌面或其它窗口——这是**有意取舍**，需要那种能力时应改用专门的远程桌面方案。
- 宿主运行在托盘模式 / 无主窗口时抓不到画面，此时回报**明确原因**（「未取到可截图的窗口」）而不是静默失败。
- 截图体积较大，因此限制单张 4 MB、每设备只保留最近 5 张，并按天与总容量自动清理。

## 附：为什么不做「静默抓屏」

截图涉及教室画面与在场人员。因此除了技术实现，还有两条产品约束：

1. 教室端插件设置里有**开关**（默认允许，可关闭），关闭后服务器的截图请求会被**明确拒绝并说明原因**；
2. 每次成功截图后，教室大屏会显示一条提示，让在场的人知道「画面被抓取用于排障」。

理由是：**能远程看一眼**与**不能让教室端一无所知**并不矛盾；把能力做出来同时把知情权做实，
才可能在学校里长期用下去。
