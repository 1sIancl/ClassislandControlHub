# 架构决策记录（ADR）

记录**已经做过的、以后可能有人想推翻的**技术决策：为什么这么选、代价是什么、什么情况下应该重新考虑。

格式统一为：状态 / 日期 / 背景 / 决策 / 理由 / 代价与限制 / 何时推翻。

| [0002](0002-permission-model.md) | 权限按模块授权，且默认拒绝（fail-closed） | 已接受 |
| [0003](0003-freeze-plugin-protocol.md) | 先冻结插件扩展协议，再写实现 | 已接受 |
| [0004](0004-render-pipeline-screenshot.md) | 远程截图走应用渲染管线，不用系统级抓屏 | 已接受 |

## 什么时候该写一篇 ADR

- 一个决定**以后有人很可能想改回去**（例如「为什么不用 WebSocket」）；
- 决策的**理由不在代码里能看出来**（例如「为什么截图不用 GDI」，代码里只能看到「用了渲染管线」）；
- 决策有**明确代价**需要后人知道（例如「删除不收缩文件、要停服 VACUUM」）。

## 怎么写

新建 `NNNN-短标题.md`，编号顺延，然后在上表加一行。**不要修改已接受 ADR 的结论**：
要改就写一篇新的，并在新 ADR 里说明「本篇取代 000X」。
