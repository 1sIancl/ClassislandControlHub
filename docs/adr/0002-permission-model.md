# ADR-0002：权限按模块授权，且默认拒绝（fail-closed）

- 状态：已接受
- 日期：2026-09（回填记录）
- 相关：[docs/security.md](../security.md)、[ADR-0003](0003-freeze-plugin-protocol.md)

## 背景

集控的使用者不是一个人：管理员、教务、电教委员、值班老师的职责边界不同。而系统里既有只读操作
（看课表、看设备状态），也有非常敏感的操作（远程命令行、抓屏、关机、改档案）。
如果只有「管理员 / 非管理员」两档，实际运行结果一定是**所有人都拿管理员账号**——这是最常见的失守方式。

## 决策

1. 权限拆分到**模块级**（设备 / 配置 / 远程 / 系统 / 审计 / 用户等），每个管理端接口在注册时**显式声明**
   所需权限键：`group.MapGet("/devices", ...).RequirePermission(PermissionKeys.DevicesRead)`。
2. **fail-closed**：没有声明权限的接口不对外开放；未识别的权限键一律视为「不授予」；未知请求直接拒绝，
   而**不是**因为「可能是新版本客户端」而放行。
3. 提供**岗位角色模板**用于批量套用常见组合，允许覆盖到具体账号。
4. 敏感能力额外加一层**非权限控制**（权限之外的第二道闸）：
   - 关机 / 重启这类不可逆操作有 15 秒**撤销窗口**；
   - 抓屏在**教室端有开关**，且执行时在大屏显示提示；
   - 下发配置前有**差异预览**，让人在点下去之前知道会改什么。

## 理由

- **显式声明**让「谁能在什么情况下调用什么」变成可审计的代码事实，而不是散落在各 handler 里的
  `if (session.IsAdmin)` 判断。
- **fail-closed** 是安全设计的基本盘：新增接口时忘记授权 → 结果是「用不了」（可发现、可修复），
  而不是「谁都能用」（可能很久都没人发现）。
- **权限之外的第二道闸**是因为权限解决的是「谁可以」，而现实风险常来自「有权限的人点错了」——
  撤销窗口、教室端开关、差异预览都是在防手滑与误伤。

## 代价

- 新增权限键需要**同时更新权限模板**，否则老账号拿不到——这是已知的运营成本，已写进贡献指南。
- 权限粒度到模块级，不做到「某台设备」级别；大规模部署中若需要更细粒度，可后续按分组扩展。

## 验证方式

每个接口的权限要求都能在代码里直接读到（`RequirePermission(...)`），并可用低权限账号实测：
无权限时应得到 `FORBIDDEN`，而**不是**静默成功或 200 空数据。
