# 升级指南

> 独立成篇（路线图 #99）。覆盖从旧版本升到 1.5.x 的完整路径：升级前要做什么、三种升级方式、
> 升级后要确认什么、出问题怎么退回来。

## 一、升级前（三件事，五分钟）

1. **先备份**。「系统维护 → 备份与恢复」里点「新建备份」，勾上**加密密钥**——
   恢复备份时如果密钥对不上，注册码 / Webhook 密钥会全部解不开（症状是「恢复完注册码全失效」）。
2. **确认数据目录在哪**（「服务器信息」页有显示）。整机搬迁 / 换机器时，数据库与密钥必须一起搬。
3. **教室端插件**：插件 id 一直是 `classislandcontrolhub.client`，**不需要卸载重装**；
   但入口程序集自 1.4.4 起改名为 `IslandHub.Plugin.dll`，**手动安装时请先清空旧的插件文件夹再解压**
   （否则旧的 `ControlHub.Plugin.dll` 残留在目录里，宿主可能加载到旧的那份，表现为「升级了却像没升级」）。
   走「插件市场」分发则自动处理，无需关心。

## 二、三种升级方式

| 方式 | 适用 | 做法 |
|---|---|---|
| **自动更新**（推荐） | 服务器能访问 GitHub | 「系统维护 → 自动更新 → 检查更新 → 立即更新」。更新**保留数据目录**，不影响已接入的设备。 |
| **手动替换** | 内网 / 离线 | 从 Release 下载对应平台的 zip，停服后解压覆盖程序目录（**不要碰 `data/`**），再启动。 |
| **Linux / systemd** | 生产 | 同上，或直接用自动更新：更新完进程退出，systemd 的 `Restart=always` 会自动拉起新版本。 |

> ⚠️ 非超级管理员点「立即更新」同样要走**操作审批**（1.5 起）：这类操作会换掉整个程序目录，
> 由超级管理员在「系统 → 操作审批」里确认后才执行。

## 三、升级后要确认的四件事

1. **版本号**：「服务器信息」页应显示新版本；`/server/info` 也能看。
2. **待处理的审批**：升级前如果有人提交过审批申请，去「系统 → 操作审批」看一眼（待审批的申请不会自己消失）。
3. **教室端是否跟上**：设备列表里应保持「已同步」；有掉线的等一个心跳周期（默认 30 秒）再看。
4. **看一眼大屏看板**（可选）：四个大数字（在线 / 离线 / 待同步）与 `/server/info` 完全一致，
   是确认「服务器自己觉得一切正常」的最快方式。

## 四、出问题怎么退回来

按代价从低到高：

1. **回滚程序版本**（1.5 新增）：「系统维护 → 自动更新」卡片里列出**程序文件快照**
   （每次自动更新前自动拍、只留最近 3 份），点「回滚到这个版本」即可。
   回滚前会自动再拍一份，所以**回滚错了也能再退回来**。回滚只换程序文件，**不动数据**。
   - ⚠️ Windows 上正在运行的 dll 无法覆盖，这些文件会被跳过并在结果里报 `skipped`，
     **重启服务后**完成回滚；Linux 上同理需要重启（或由 systemd 拉起）。
2. **从备份恢复**：会**整库覆盖**（数据 + 配置一起退回），所以要走操作审批；恢复后需重启服务。
3. **重装**：最后一招。装完用备份恢复，或用「数据迁移」把配置搬回来。

## 五、版本兼容

见 [`README.md`](../README.md) 的「版本兼容」表：哪些 A 端 / 插件组合可以直接安装、哪些需要先升级另一边。
教室端插件与 A 端**不必同版本**，但差得太多会报「协议不支持」——两边升到同一版本最省事。

## 六、常见升级问题

| 现象 | 原因 / 处理 |
|---|---|
| 恢复备份后注册码全失效 | 密钥没一起恢复。见 [`faq.md`](faq.md) 的对应条目。 |
| 升级后配置像被重置 | 配置在**数据目录**里，不会因为换程序文件而丢；若用了新的数据目录路径，那是「换了库」而不是「丢了配置」。 |
| 自动更新卡在「正在更新」 | 下载被网络中断。重试一次；持续失败就改用手动替换。 |
