# 故障排查指南

按「症状 → 先看哪里 → 常见原因」组织。排查时请优先**看界面给的结论**：从 1.3.2 起设备列表会直接写清离线原因
（从未连接 / 已停用 / 离线多久 + 最近报错），指令队列会写清「为什么还没执行」。

---

## 0. 三个万能入口

| 入口 | 能看到什么 |
|---|---|
| `GET /api/v1/server/info` | 服务端版本、启动时间、运行时长（**重启后应归零**，可据此确认重启是否生效）、在线/待同步设备数、数据目录 |
| `GET /api/health` | 进程存活与基本健康状态 |
| 「系统设置 → 服务器信息」 | 同上，界面版；含数据目录路径与端口 |

```bash
curl http://127.0.0.1:29800/api/v1/server/info
```

## 1. 管理界面打不开

| 可能原因 | 怎么确认 | 处理 |
|---|---|---|
| 服务端没启动 | `GET /api/health` 无响应 | 双击 `启动A端服务器.bat`（Windows）或 `systemctl status classisland-controlhub`（Linux） |
| 端口被占用 | 启动日志报 `address already in use` | 换端口（`ControlHub:HttpPort`），或停掉占用进程：`Get-NetTCPConnection -LocalPort 29800 -State Listen` |
| 防火墙拦住 | 本机能开、别的机器打不开 | 放行端口（`sh/install-windows.ps1` 会自动放行；Linux 用 `ufw`/`firewalld`） |
| 浏览器缓存旧界面 | 界面元素缺失或行为异常 | **强制刷新**（Ctrl+F5）。前端升级会改 `?v=NN`，但页面本身可能被缓存 |
| HTTPS 证书未信任 | 浏览器停在「不安全」警告 | 自签名证书见 `docs/deployment.md`；学校内网也可先用 HTTP + 只在内网开放 |

## 2. 教室端设备不出现 / 一直离线

1. **先在设备列表看「离线原因」**，它会直接告诉你属于哪一类：
   - 「从未连接」→ 设备注册了但一次心跳都没有：**优先查插件里的服务器地址与网络**（见下）。
   - 「已离线 X 分钟，最近一次报错：…」→ 报错内容通常就是根因（证书、DNS、超时）。
   - 「已被停用」→ 在设备列表恢复，或重新注册。
2. 「从未连接」的排查顺序：
   - 插件设置里的**服务器地址**是否可从教室机访问（用教室机浏览器打开 `http://服务器IP:29800` 试）；
   - 注册码是否**过期 / 用完 / 被禁用**（注册码页面能看到已用次数）；
   - 教室机是否走了代理 / 需要放行出站；
   - HTTPS + 自签名证书：插件需勾选「允许不安全 TLS（自签名）」或改用受信任证书。
3. 设备能连上但状态在「离线/在线」之间跳：检查 `ControlHub:OnlineTimeoutSeconds`（默认 120 秒，心跳为它的 1/4）
   是否被调得过大，以及教室机是否休眠。

## 3. 配置不下发 / 设备一直「待同步」

- 设备在「在线」但仍待同步：看它 `appliedRevision` 与服务器 `serverRevision` 是否一致；
  长轮询连接被中间设备（反向代理）掐断会导致收不到推送——**反代要放行长连接并调大超时**（`/client/wait` 最长挂 60 秒）。
- 推送了但只有一部分设备刷新：确认推送范围（分组是否是你以为的那一层），
  以及是否开了分批下发（`PushBatchSize`，批间有间隔，属正常延迟）。
- **下发前想看会改什么**：配置下发页点「立即推送」会先弹差异预览（新增 / 删除 / 修改）。
  若显示「没有可对比的基线」，说明该设备还没成功应用过配置——先让它上线同步一次。

## 4. 远程指令发出去了但没执行

1. 看「待执行指令队列」：排队原因写得很直白——
   - 「设备当前离线，将在下次上线心跳时立即执行」→ 设备没在线。
   - 「定时指令：…生效后执行」→ 你用了延迟/定时下发。
   - 「设备已取走指令，正在执行」→ 已派发，等回报。
2. 指令有 **2 小时 TTL**，超时作废（队列里显示剩余时间）；关机 / 重启这类不可逆操作有 **15 秒撤销窗口**。
3. 广播后看**结果面板**：逐台显示成功 / 失败 / 过期，失败原因在输出里。
4. 插件版本太老：`diagnostic.*` 之类的**新指令会回报「不支持的指令类型」**——教室端插件需一起升级。

## 5. 截图失败 / 截图全黑

- 本项目抓的是 **ClassIsland 主界面的渲染画面**（教室端通常全屏，即学生看到的内容），不是系统桌面截图。
  **这是有意为之**：用系统级 GDI 抓屏拿到硬件加速窗口很容易得到全黑图。
- 回报「未取到可截图的窗口」→ 宿主可能运行在托盘模式 / 无主窗口状态。
- 教室端关闭了「允许管理端远程抓取本机画面」→ 指令会被**明确拒绝并说明原因**（不会静默失败）。
- 上传失败提示过大 → 单张上限 4 MB；降低分辨率或改用「前台进程」这类轻量诊断。

## 6. 磁盘越用越大

| 数据 | 默认保留 | 配置项 |
|---|---|---|
| 客户端日志 | 30 天 | `ControlHub:ClientLogRetentionDays` |
| 审计日志 | 见 `ControlHub:AuditLogRetentionDays` | 同上 |
| 远程指令历史 | 30 天 | `ControlHub:CommandRetentionDays` |
| 诊断截图 | 30 天 + 总量上限 512 MB | `DiagnosticRetentionDays` / `DiagnosticMaxTotalMb`（超出后从最旧的删） |

- 单设备截图另有「只保留最近 5 张」的硬限制，防止反复抓屏撑爆数据库。
- SQLite 删除记录后**文件不会自动收缩**（页会被复用，容量不再增长）。需要真正缩小文件时停服后执行
  `VACUUM`（见 `docs/deployment.md`）。
- **数据目录不要放在网络盘 / 同步盘**：SQLite 对文件锁敏感，会随机出现「database is locked」。

## 7. 数据库异常 / 启动报错

- `database is locked`：多为网络盘、杀软实时扫描或另一个实例同时打开同一数据目录所致。停掉多余实例，换本地 SSD。
- 启动时自动建表与补列（老库升级走 `EnsureColumnAsync`），**不要手改表结构**：改完再启动会被补列逻辑覆盖理解。
- 恢复：用「系统设置 → 备份」的备份文件恢复（升级前会自动备份）；恢复前先停服并留一份现场副本。

## 8. Webhook 通知收不到

- 在「系统设置 → Webhook 外部通知」点**测试发送**：失败会告诉你具体原因（HTTP 状态码 / 签名错误 / 超时）。
- 钉钉必须填加签密钥；企业微信 / 飞书用的是机器人 Webhook 地址，注意不要贴成管理后台地址。
- 只订阅了部分事件：检查该 Webhook 的事件勾选（设备掉线 / 同步失败 / 指令失败等）。

## 9. 桌面外壳相关（仅 Windows）

- 提示缺少 WebView2 → 装 [WebView2 运行时](https://developer.microsoft.com/microsoft-edge/webview2/)（Win11 一般自带）。
- 本机免登录不生效 → 只对**回环地址 + 令牌**有效，且依赖数据目录里的 `local-shell.token`；从别的机器访问仍需登录。
- 退出时把服务一起停了 → 外壳只停「自己启动的进程」；用 `--no-stop-on-exit` 可保持。
- 想看外壳在做什么：`--check` 自检环境，`--smoke` 无界面跑通整条链路。

## 10. 注册码失效 / Webhook 报「密钥不可用」/ 加密计数异常（#36）

**表现**：启动日志出现「静态敏感数据：存在无法解密的值」，或管理端「系统设置 → 服务器信息」的
「敏感数据加密」显示「N 条无法解密」；教室端注册提示注册码不存在、Webhook 投递报密钥无法解密。
个别行的注册码列显示「不可用」badge。

**原因（按可能性排序）**：

1. **密钥文件被更换 / 丢失**（最多见）：换机器或恢复备份时只搬了 `controlhub.db`，没搬 `secrets.key`；
   或数据目录被清过、密钥文件被杀软隔离。此时旧密文无法解开——**数据本身没坏，但必须找回原密钥**。
2. 手工改了数据库里的注册码行（比如直接 INSERT 明文一条又没补 `code_hash`）——启动迁移会补上，重启一次即可。
3. 密钥文件权限/内容被破坏（例如被文本编辑器改过、编码变化）→ 服务启动时会直接报错，不会静默换新密钥。

**处置**：

- 找回原密钥文件（备份、旧机器、快照）放回数据目录，重启服务即恢复——**优先做这一步**。
- 确认无法找回：密钥文件丢失后数据不可逆，只能重建——
  重新生成注册码 / 邀请码；到 Webhook 编辑页重新填写加签密钥。
  停在列表里显示「不可用」的旧行可以直接删除（界面上用指纹引用 `ref:xxxxxxxx` 标识，删除按钮仍可用）。
- **事后**：把 `secrets.key` 纳入备份与外发排除清单的说明（见 `docs/security.md` 第六节），
  换机器时**数据库和密钥文件一起搬**（见 `docs/deployment.md`）。

## 11. 还是解决不了

收集这些信息再提问（能大幅减少来回）：

1. `GET /api/v1/server/info` 的返回；
2. 出问题设备的「离线原因」文本与最近一次报错；
3. 相关指令队列条目 / 命令历史里的输出；
4. 远程诊断的**诊断数据包**（含版本、环境、最近日志），或「设备 → 运行日志」里的片段；
5. 服务端日志中同一时间段的报错行。

提交 Issue 请用仓库的 Bug 模板（会引导你填齐上面这些）。
