# 档案编辑器与时间表的操作逻辑：改进目标与预期效果

> 本文只写**要达成什么、用户会感觉到什么**，不写实现方式与改动范围。
> 目的是先把“顺不顺手”说清楚，避免一上来就改代码，改完才发现改的不是痛处。

## 一、现状（基于当前实现的事实，不是猜测）

| 环节 | 现在的行为 | 摩擦在哪 |
|---|---|---|
| 保存 | 只有一个「保存并下发」按钮 | 想改一点内容又不想惊动教室，没有第二条路；手滑点下去就是全校生效 |
| 删除档案 | 弹窗确认 → 直接删 | 确认之后无法反悔（知道有留档，但入口在别处，不在手边） |
| 版本回退 | 后端有版本接口，界面没有入口 | 改坏了只能找人从数据库捞 |
| 离开页面 | 有脏标记，但没有拦截 | 切页 / 关标签，改动直接没了 |
| 撤销 | 只有个别操作有「撤销」提示条（如删除项） | 改错一个时间要手动改回来；没有通用的 Ctrl+Z |
| 时间表排序 | 编辑时顺序不变，保存时按时间排 | 拖完看着还在原位，心里没底“到底生效没有” |
| 冲突检测 | 无 | 两个时间点重叠、上课点零时长、跨零点，全都静默通过，教室里才会发现 |
| 批量操作 | 无 | 删 5 个时间点要点 5 次、确认 5 次 |

## 二、档案编辑：目标与预期效果

### 2.1 保存要分级，不要让「改个字」和「换整套作息」用同一个按钮

**目标**：把「保存」与「让教室端生效」拆成两个意图明确的动作。

**预期效果**

- 改完点「保存」：内容进库、版本可回溯，**教室端不受影响**，按钮旁明确写「尚未下发到教室」。
- 点「保存并下发」：明确作用于教室端，并显示将影响多少台设备 / 哪些班级。
- 记不清上次有没有下发时，页面上能直接看出「库里的版本」与「教室端正在用的版本」是否一致。

### 2.2 未保存的改动不能悄悄消失

**目标**：只要还有未保存改动，离开就必须有明确结果。

**预期效果**

- 切页、切换页签、关标签、刷新时给出选择：保存 / 放弃 / 留下。
- 不做那种“弹了三次用户就学会闭眼点确定”的拦截——只有**真的会丢内容**时才拦。

### 2.3 删除要可反悔，而不是“确认过了就别后悔”

**目标**：删除是可逆操作，反悔成本不超过 10 秒。

**预期效果**

- 删除后右下角出现「已删除，撤销」提示条，点一下整份恢复，位置与内容与删除前一致。
- 超过撤销窗口后仍可从「已删除」列表找回（这条已经具备，目标是把入口放到用户手边）。
- 删除前明确告诉用户：**课表会一起留档、时间表不会删**——避免“删了档案会不会把共用作息也删了”的担心。

### 2.4 版本回退要能在界面上完成

**目标**：改坏了不必找人，自己三步内回到上一个好版本。

**预期效果**

- 编辑器内直接看到版本列表（时间、改动摘要）。
- 选中任一版本可**预览差异**（哪节课、哪个时间点变了），再决定是否回退。
- 回退本身也产生一个新版本，因此“回退错了”还能再回来。

### 2.5 危险操作与普通操作要长得不一样

**目标**：误操作概率与操作的危险程度成正比。

**预期效果**

- 「保存并下发」「删除档案」「清空课表」这类动作有明确的危险样式与二次确认。
- 「加一个时间点」「改个名字」这类高频动作**不打扰**，不再弹确认。
- 单页内危险按钮不与常用按钮相邻摆放。

## 三、时间表：目标与预期效果

### 3.1 添加与调整要“看得见结果”

**目标**：任何一次调整，用户都能立刻确认“改对了”。

**预期效果**

- 新增时间点默认接在最后一个之后（上课 45 分钟、课间 10 分钟），不用每次都改两遍时间。
- 拖动 / 改数值后，时间轴、表格、顶部统计**同时**更新，不出现“一边变了一边没变”。
- 改完后若与相邻时间点冲突，当场在那一行标出来，而不是等到保存才报。

### 3.2 排序必须是确定的，且不需要用户操心

**目标**：时间点永远按时间先后呈现，用户不需要手动排序。

**预期效果**

- 任何改动后（拖动、手改时间、新增）自动归位。
- 出现“排在后面但时间更早”的情况时，界面直接纠正并给出一次轻提示，而不是让用户自己发现。
- 允许一键按时间重排，用于导入数据或手工乱序之后。

### 3.3 冲突检测要在编辑时就说话

**目标**：把“教室里才发现的问题”提前到编辑时。

需要覆盖的情况与预期提示：

| 情况 | 预期效果 |
|---|---|
| 两个时间点时间重叠 | 两行同时标红，提示重叠了多久，并给出「顺延后一个」的一键修正 |
| 上课点零时长或结束早于开始 | 行内标红，保存被挡下并给出原因 |
| 课间与上课重叠 | 同上，并区分“课间吃掉了上课时间” |
| 跨零点（如 23:50–00:20） | 明确提示跨天，避免被当成负时长 |
| 时间点为空 | 保存前汇总提示，而不是静默丢弃 |

**预期效果（汇总层）**

- 保存前，若有未解决的冲突，**阻断保存**并列出全部问题（不是只报第一条）。
- 若无冲突，保存一路顺畅，不再有额外的确认弹窗。
- 冲突提示说明“会有什么后果”，而不只是说“不合法”。

### 3.4 批量操作

**目标**：成组修改不必逐个来。

**预期效果**

- 多选后批量删除、批量改类型、批量平移（整体提前/推后 N 分钟）。
- 批量删除只需确认一次，且可整体撤销。
- 批量操作的影响范围在确认框里写清（“将删除 6 个时间点，涉及 3 张课表”）。

### 3.5 撤销与重做

**目标**：编辑过程可回溯，不必靠“记住了再改回来”。

**预期效果**

- 支持 Ctrl+Z / Ctrl+Shift+Z（以及按钮），覆盖时间点的增删改、拖动、类型变更、名称修改。
- 撤销粒度是“一次操作”，不是“一次按键”——拖动一次算一步。
- 撤销后界面状态（选中项、滚动位置）尽量保持，不做跳跃式重绘。
- 保存后撤销栈清空或标记为不可跨保存回退，避免“撤销回保存前又忘了没保存”。

## 四、状态与反馈：一致性

**目标**：同样的操作，在任何地方都给出同样的反馈。

**预期效果**

- 所有保存类操作：进行中（按钮禁用 + 进度）、成功（明确说“已保存/已下发”）、失败（说明原因 + 可重试）。
- 失败时**不丢用户已输入的内容**，不要求重新填一遍。
- 长耗时操作（下发、批量）有可中断的进度，不是无响应。
- 提示条不叠加：连续操作时后一条替换前一条，或合并成一条带计数的提示。

## 五、边界：这些不做

- **不做实时多人协同编辑**：两个人同时改同一份档案，仍以“后保存覆盖”为准，但保存前会提示“这份档案在你打开之后被改过”。
- **不把冲突检测做成强制锁**：冲突可以被忽略并保存（由用户明确选择），因为总有“故意的重叠”。
- **不引入复杂的操作日志 UI**：版本历史已能承担回溯职责，不再单独做操作流水。

## 六、怎么判断改到位了（可观察指标）

不看代码，只看行为：

1. 改一个字再想把改动给教室——不需要重新回忆“上次下发是几点”。
2. 手滑删掉档案——10 秒内能点「撤销」，内容完全回来。
3. 改坏了一整天——在编辑器里回退到上一版本，且能先看差异。
4. 拖错一个时间点——Ctrl+Z 一次回到原位。
5. 排一节课到别一节课里——当场看到红色与“重叠 12 分钟”，并且有一键顺延。
6. 删 6 个时间点——选一次、确认一次、后悔一次就能全回来。
