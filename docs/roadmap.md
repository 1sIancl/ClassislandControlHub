# 路线图与建议清单

本文件是项目 backlog 的单一事实来源：按优先级分组，每条都标注当前状态，避免「提过但没人记得做没做」。

状态标记：

| 标记 | 含义 |
|---|---|
| ✅ | 已完成（含已完成但实现方式不同的情况，会在条目里说明） |
| 🔨 | 部分完成，已实现主线、还缺若干细节 |
| ⬜ | 待办 |

> 落地原则：**先冻结协议，再写实现**（见 [插件扩展协议](plugin-protocol.md)）。协议反复改的代价远大于功能晚一点上。

## 建议的推进顺序

1. **P0 剩余两项**（#4 指令队列可视化、#5 下发 diff 预览）——都在现有数据之上，改动集中在 Web 端。
2. **协议落地**：按 [plugin-protocol.md](plugin-protocol.md) 实现能力注册与 A 端自动表单，这是「从工具走向平台」的唯一路径。
3. **运维短板收口**：P1 的 #7 通知回执、#8 审计筛选导出、#16 批量结果面板、#18 分批下发。
4. **质量基建**：#78 单元测试、#79 集成测试、#77 CI 跑 smoke、#94 CHANGELOG。
5. 其余按「用户痛点 × 改动成本」排序，不建议并行铺开。
