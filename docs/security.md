# 安全加固指南

面向**准备在学校内网正式部署**的管理员。目标是：即使部署在内网、即使操作者是电教委员而非安全工程师，
也不至于出现「谁都能进后台」「教室被远程随意摆布」这类问题。

---

## 一、部署前检查清单（按顺序做）

- [ ] **改掉默认管理员密码**，并为每位使用者建独立账号（不要共用 `admin`）。
- [ ] 打开**两步验证（TOTP）**：「系统设置 → 账号安全」，管理员账号尤其要开。
- [ ] 按岗位分配权限（设备 / 配置 / 远程 / 系统 / 审计等按模块授权），遵循最小权限。
- [ ] 不要把管理端口暴露到公网。确需外部访问时，走 VPN 或只放行必要来源（反代 + 来源限制）。
- [ ] 需要 HTTPS 时用**受信任证书**；自签名只在完全可控的内网使用，并明确告知使用者。
- [ ] 确认数据目录在**本地磁盘**、已纳入备份，且不是人人可写的共享目录。
- [ ] 关闭不需要的能力（例如教室端不需要被截图时，让教师在插件设置里关掉「远程协助与隐私」）。
- [ ] 配好**管理端来源限制**（`ControlHub:AdminIpAllowList`，例如只允许办公网段 192.168.10.0/24），
      并按[安全自检清单](security-testing.md)第 5/6 条**正反两向**验证：拦得住、且没误伤自己。
- [ ] 确认**登录失败锁定**生效（默认连错 5 次锁 15 分钟），需要时调 `LoginMaxFailures` / `LoginLockoutMinutes`。
- [ ] 确认**安全响应头**与 **API 访问日志**开启（默认开启）；需要接日志平台时把 `ControlHub:LogJson` 打开。
- [ ] 约定**审计日志**的查看与保留期限，重要操作（换课、广播、远程指令、诊断）定期抽查。

## 二、信任边界（先把这三条想清楚）

1. **管理端接口只认 `Authorization` 头**
   管理端全部接口都要求登录令牌，权限判定是 **fail-closed**（没有声明的接口不对外开放；权限不足直接拒绝）。
   因此**不要**把管理端接口套在「内网就免鉴权」的反代规则里。

2. **本机免登录只对回环地址生效**
   桌面外壳通过数据目录里的 `local-shell.token` 实现本机免登录，**只在回环地址 + 令牌同时满足**时生效；
   从局域网 IP 访问仍然要求登录。若要彻底关闭这条通道，删掉该令牌文件并不要用外壳启动。

3. **教室端令牌按设备隔离**
   B 端用 `HubDevice <token>` 鉴权，且回报 / 拉取指令都会带设备身份校验——
   一个设备的令牌**不能**回报或覆盖其它设备的指令。设备丢失或被人借走时，请在设备列表**停用**它。

## 三、传输与网络

| 项 | 建议 |
|---|---|
| 协议 | 内网也建议 HTTPS（防被动监听、防投毒），证书优先用学校统一证书 |
| 端口 | 只开放服务端口；用反代时注意**长轮询要放行长连接**（`/client/wait` 最长挂 60 秒） |
| 出站 | 教室端只需能访问集控服务器；如需外网通知（企微 / 钉钉 / 飞书）再放行对应域名 |
| 代理 | 若教室机走代理，确保集控服务器地址在**直连**例外列表里 |

## 四、远程能力与隐私

集控具备远程能力，因此**默认就该被管住**：

| 能力 | 风险 | 现有控制 |
|---|---|---|
| 远程命令行 | 可在教室机执行任意命令 | 需要 `remote.write` 权限；每条指令进审计与命令历史 |
| 屏幕截图 | 涉及教室画面与在场人员 | **教室端开关**（插件设置「远程协助与隐私」）+ 截图时在大屏显示提示 + 日志可查 |
| 前台进程 / 诊断数据包 | 可能含路径、账号等敏感信息 | 需 `remote.read`；内容随保留策略自动清理 |
| 电源操作（关机 / 重启） | 不可逆 | **15 秒撤销窗口** + 队列可视化可取消 |
| 配置下发 | 换错档案会影响整栋楼 | **下发前差异预览**（新增 / 删除 / 修改清单） |

约定：**抓屏与命令行只用于排障，用完即止**；截图默认每设备只保留最近 5 张并按天 / 按容量自动清理。

## 五、账号与会话

- 密码强度有强制校验；**两步验证**建议对所有能下发配置或执行远程指令的账号开启。
- 会话有效期由 `ControlHub:SessionLifetimeHours` 控制，公共场所使用后请主动退出。
- 权限按模块授予：看不到的模块就不该授权。岗位模板可用于批量套用常见组合。
- 账号离职 / 换岗时：**改密码 + 复查权限 + 查该账号的审计记录**。

## 六、数据与备份

- 备份文件包含账号、设备令牌、档案内容与审计日志——**按机密数据对待**（加密保存、限定可读范围）。
- 迁移 / 恢复前先停服；恢复后确认设备能重新心跳（令牌随备份一起恢复）。
- 定期导出审计日志留存（排查与合规需要），并按学校制度定期清理历史日志。

## 七、已内置的安全控制（可直接用）

| 控制 | 配置项 | 默认 |
|---|---|---|
| 安全响应头（CSP / X-Frame-Options / nosniff / Referrer-Policy / Permissions-Policy；HTTPS 下附带 HSTS） | `SecurityHeadersEnabled` | 开启 |
| 管理端来源限制（IP 或 CIDR，只约束 `/api/v1/admin`；回环始终放行） | `AdminIpAllowList` | 不限制 |
| 登录失败锁定（按账号计数，窗口内连错即锁） | `LoginMaxFailures` / `LoginLockoutMinutes` | 5 次 / 15 分钟 |
| HTTPS 强制跳转（回环不跳转，避免桌面外壳免登录失效） | `RequireHttpsRedirect` | 关闭 |
| API 访问日志（方法 / 路径 / 状态 / 耗时 / 来源 / 追踪 ID；心跳与长轮询降为 Debug） | `AccessLogEnabled` | 开启 |
| 结构化 JSON 日志（便于日志平台检索） | `LogJson` | 关闭（文本日志更利于现场排查） |
| 分级健康检查：`/api/health`（兼容）、`/live`、`/ready`（数据库不可用返回 503）、`/deep`（含数据目录可写与磁盘余量） | — | — |
| 危险操作二次确认与撤销窗口、教室端截图开关、下发前差异预览 | — | — |

启动日志会回显这些开关的实际状态——**先确认日志里写的是你要的，再相信配置生效了**。

## 八、当前已知限制（不要当成已解决）

诚实列出，避免误判安全水位：

1. **注册码与 Webhook 密钥以明文存储在数据库中**（账号密码是哈希）。数据库泄露时这些需要轮换——
   注册码可随时作废重发，Webhook 密钥需到对应平台重置。
2. **没有逐请求的访问日志表**：访问日志写在服务端日志文件里，数据库里只有管理端关键操作的审计记录。
3. 教室端令牌若被完整复制，攻击者可冒充该设备（这是对称令牌的固有限制）；发现异常时停用设备并重新注册。
4. **没有代码级漏洞扫描**：Dependabot 只提醒依赖版本更新，不做静态代码扫描与渗透测试自动化。

> 上面几条都在 [`roadmap.md`](roadmap.md) 的待办里；在那之前，请用网络层手段（防火墙、反代来源限制、VPN）补足。
> 自检步骤见[安全自检清单](security-testing.md)。

## 八、出事之后的处置顺序

1. **先止损**：停用涉事设备 / 停用相关账号，必要时停服。
2. **留证据**：复制数据目录与备份，导出审计日志与相关命令历史（不要在原库上继续操作）。
3. **查范围**：审计日志按时间轴看「谁在什么时候做了什么」；命令历史看远程指令与输出；诊断记录看是否有人抓过屏。
4. **换密钥**：重置涉事账号密码与两步验证、作废注册码、重置 Webhook 密钥、必要时恢复备份。
5. **写下来**：把经过与改进项补进本文件或 Issue，避免同类问题再发生。
